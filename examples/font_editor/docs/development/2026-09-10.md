## BUG-002 — quantized rendering and saving repaired

The author reported that quantized fonts saved as thresholded output. Created
BUG-002 in the root TODO before implementation and completed its four work items.
The task is closed and removed from the unfinished-work index; current behavior
is recorded in [`document-io.md`](../document-io.md). The frozen audit remains
unchanged. This adds a concrete finding: the quantized/grayscale UI choices had
no rendering branches, and the four-color helper was never called.

1. The default Save format was `.font`, whose existing writer stores one bit
   per pixel and thresholds the image. Changing only its metadata would falsely
   claim to preserve shades. Quantized, grayscale and palette modes now default
   to PNG; threshold mode defaults to the explicitly labeled monochrome format.
2. Quantized rendering now maps to the nearest of 0/85/170/255 with no dithering.
   Grayscale rendering converts to grayscale. Fixed gray levels make repeated
   quantization stable and avoid image-dependent palette changes on reopen.
3. PNG Save writes the actual atlas plus a normalized sidecar retaining its
   raster choice and colors. The shared metadata helper gives both PNG and
   monochrome exports actual cell dimensions and zero transformations, without
   mutating live settings. PNG import uses ceiling row counts and validates
   image/grid divisibility. XML source recursion returns the rendered source
   directly rather than applying its transforms a second time.
4. Save uses its actual selected type for extensionless filenames and honors
   known explicit extensions. During review, local Tk 9.0 source showed that a
   fixed `defaultextension` prevents a later filter selection from changing the
   appended extension. An actual file-dialog regression reproduced this as
   `native-mono.png` after selecting monochrome. Letting Tk derive the extension
   from the active filter fixes the case; the real dialog now returns `.font`.
5. All three initial regressions failed against the prior implementation:
   quantized rendering retained intermediate levels, PNG Save was unsupported,
   and format defaults were absent. Four final tests cover rendering boundaries,
   stable gray levels, PNG pixel/metadata round trips with partial rows and a
   hand edit, unchanged live settings, default/explicit formats, cancellation,
   actual application reopening and the actual Tk file-type switch.

   5.702 seconds. Two new pixel/data probes explicitly remove both DISPLAY and
   WAYLAND_DISPLAY. `git diff --check` passed, and the frozen audit plus working
   app/default font XML and preview PNG retained their pre-work hashes.

## Author-authorized progress checkpoint before resampling experiments

The author requested a progress commit of the current font-editor code, tests
and documentation before implementing per-character resampling optimization.
This checkpoints UI-001, UI-003/UI-004, the frozen AUDIT-001 report and BUG-001
through BUG-003. Working recent-file preferences, default font settings and
the generated preview PNG remain local; unrelated projects are excluded.

Investigation of the latest offset report found identical hashes on repeated
renders at identical settings. The author confirmed the observed effect is
different antialiasing at different offsets. Current offsets translate the
entire source sheet before resampling, so they change sampling phase and allow
neighbouring glyph pixels to cross boundaries. A synthetic two-glyph probe
reproduced that leakage. The author's next approved experiment is a commanded,
per-character bounded sampling-phase search maximizing brightness, with faithful
position offsets independent of that search. Existing recipes must retain their
old interpretation until explicitly converted. Search parameters need not be
serialized; applying the result creates edited pixels, subject to the existing
PNG-versus-source-recipe persistence boundary.
