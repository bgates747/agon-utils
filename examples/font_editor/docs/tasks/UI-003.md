# UI-003 — Restore character editing and resolve the reported click hang

Status: **Completed under delegated implementation authority; uncommitted.**
Created: 2026-09-10.
Completed: 2026-09-10; removed from the unfinished-work index.

The author reports that clicking a glyph in the atlas should open an editor
window but instead hangs the application. The author authorized implementation
and verification without a further approval gate, with all changes uncommitted.

1. [x] Investigate the click path and rendering lifecycle; distinguish reproduced
   defects from unconfirmed causes of the reported hang.
2. [x] Open a responsive character editor for valid glyph clicks, reuse its
   window for another selection, and support closing/reopening it safely.
3. [x] Load the actual selected glyph into the editable pixel state and update
   the correct atlas glyph when a pixel changes. Preserve edits when switching
   glyphs and in ordinary `.font` exports.
4. [x] Keep redraw work bounded and reject clicks outside actual glyph cells.
   Validate repeated selections, pixel edits, redraws, and window lifecycle.

The accepted application UI scaling remains in effect. The editor should allow
continued interaction with the atlas rather than holding a modal input grab.
The original simple click did not hang in the isolated reproduction, but could
not open an editor because it was disabled. Redraws accumulated canvas image
items (2 initially, 52 after 50 redraws). Restored the editor, removed the growing
display list and resize-triggered rerasterization, and fixed the editor's stale
pixel state. No claim is made that the exact original hang was reproduced.

Actual Tk click bindings, repeated selections/edits, event-loop responsiveness,
close/reopen, correct glyph data, and saved `.font` bit changes pass integration
tests. See the [development evidence](../development/2026-09-10.md) and
[current behavior](../font-grid-editor.md). The author explicitly waived a
further approval gate for these tasks; no commit was made.
