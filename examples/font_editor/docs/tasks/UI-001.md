# UI-001 — Resolve tiny widgets under Pop!_OS desktop scaling

Status: **Approved work contract — option 1 authorized, pending execution and visual review.**
Created: 2026-09-10.
Tracking: [Font Editor TODO](../../TODO.md).

## Problem and evidence

The author reports that the editor's widgets appear very small despite the
desktop's scaling settings. The cause has not been confirmed.

Read-only inspection found a COSMIC Wayland session with an X display available.
`xrdb -query` showed cursor settings but no `Xft.dpi` resource. The editor's
startup does not explicitly configure Tk scaling. This suggests a possible
desktop-to-Tk scaling mismatch, but does not establish the cause. The installed
Tk version, Tk's reported DPI and scaling, and the actual desktop scale have
not yet been measured.

The main entry point is `src/python/font_editor.py`. The UI mixes Tk and ttk
widgets and uses fixed pixel padding. `src/python/image_display.py` implements
separate font-atlas zoom. Application preferences are stored in XML.

## Options for review

1. [ ] **Try COSMIC's X11 application scaling setting.** In Settings → Displays →
   X11 Window System Application Scaling, try **Optimize for applications** and
   restart the editor. Verify the setting's availability on the installed
   COSMIC version. Record the prior setting and the observed result. This is
   a desktop-wide adjustment that may affect other X11 applications.

2. [ ] **Add a persistent application UI-scale preference.** Provide Auto and
   explicit percentages such as 100%, 150%, and 200%, saved in the application's
   XML configuration. Apply Tk scaling before constructing widgets and account
   for fixed pixel padding, control dimensions, and any explicit font sizes.
   Keep font-atlas zoom independent of UI scaling and preserve exported font
   dimensions and bytes. Define percentage semantics clearly: Tk's raw scaling
   value is pixels per point, not a desktop percentage. Decide during design
   whether changes require restarting the app; Tk does not guarantee that
   existing widgets resize correctly after a scaling change.

3. [ ] **Improve automatic scale detection.** Compare the installed Tk's version,
   windowing system, reported DPI, and scaling with COSMIC's configured display
   scale. Use reliable available information to select a startup scale, with
   a manual override and a defined fallback when detection is unavailable.
   Account for compositor scaling to avoid applying the same scale twice.
   Define behavior for monitors with different scales and for moving a window
   between them; automatic per-monitor adaptation is not yet promised.

The approved order is to try option 1 first, then consider option 2 if needed.
Option 3 is a possible refinement. The author authorized execution of option 1,
including its desktop setting adjustment, followed by launching the editor for
visual approval. Options 2 and 3 remain pending selection.

## Acceptance criteria for the selected approach

1. [ ] The author verifies that controls and text are comfortably readable at the
   intended desktop/UI scale, including menus and relevant dialogs, with no
   clipping or inaccessible controls.
2. [ ] Font-atlas zoom and exported font content retain their intended behavior.
3. [ ] If an application preference is implemented, it persists across launches
   and has documented default, override, and restart behavior.
4. [ ] If automatic detection is implemented, its source, fallback, and limitations
   are documented, including mixed-monitor behavior and double-scaling checks.
5. [ ] Verification uses the repository `.venv` and the prerequisite native-extension
   check required by the repository handoff before Python work. Record the
   actual environment and visual results when implementation is undertaken.
