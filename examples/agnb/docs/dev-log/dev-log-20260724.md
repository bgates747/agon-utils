# AGNB Development Log — 2026-07-24

## Small valid LIST records exposed an `ez80asm` precedence bug

During integration of the hardware-proven AGNB loader into AgonWolf3D, a
408-record cube-and-sprite container passed independent structural and
byte-level validation but stopped after 327 completed images with
`agnb_error_chunk` (`07`). The next record was a valid 1-by-1 transparent
RGBA2222 placeholder:

- buffer ID `0x0247`;
- LIST payload size 44 bytes;
- DATA payload size one byte containing zero; and
- three zero alignment bytes.

Runtime diagnostics proved that the reader and FatFS offsets agreed, the next
header was `LIST`, and its declared size was the correct little-endian
`0x0000002C`. Instruction-level markers isolated the failure to the minimum
LIST payload check.

The generated assembly listing revealed the cause. `ez80asm` evaluated:

```asm
agnb_list_type_size+3*agnb_chunk_header_size
```

left to right as `(4+3)*8`, emitting `0x38` (56), rather than the intended
`4+(3*8)`, or `0x1C` (28). Larger image records had hidden the defect.

The canonical reader now places the multiplication first:

```asm
3*agnb_chunk_header_size+agnb_list_type_size
```

The listing must encode `0x00001C` for this operand. AgonWolf3D was rebuilt
with the same fix and the user confirmed the complete 408-image application
loads and runs successfully. The container and placeholder were not malformed.

The canonical container harness assembled successfully after the correction,
and `images/container/src/asm/app.lst` now shows immediate bytes `11 1C 00 00`.
This result was first obtained in an incomplete duplicate checkout whose
shared processed assets were absent. The commit and subsequent working changes
were later migrated into the complete canonical checkout at
`/home/smith/Agon/mystuff/agon-utils` for full regeneration and testing.

## Consecutive-container traversal must reset reader state

AgonWolf3D exposed a second lifecycle defect after adding a 31-image
`ui.agnb` bootstrap load before its established 417-image `images.agnb` load.
The UI container completed, panels loaded from the world container, and the
reader then failed during sprites with `agnb_error_bounds` (`08`).

The physical FatFS file position correctly began the second file at zero, but
`agnb_state_file_offset` retained the completed UI container's 181,928-byte
logical position. The world traversal therefore reached its declared RIFF end
approximately 181,928 bytes early. This had remained hidden because the
canonical prototype and its hardware tests loaded only one container after
BSS initialization.

The canonical `agnb_open` now resets all four bytes of
`agnb_state_file_offset` and `agnb_state_bytes_read` for every file. The
runtime harness deliberately loads its container twice, and automated
lifecycle tests enforce both the reset and double traversal. The corrected
Wolf3D application assembled successfully and completed UI, panel, sprite,
and distance-wall loading in the emulator; the user confirmed successful
startup.

The two focused Python lifecycle tests passed in the original duplicate.
After migration, the complete canonical checkout provides the shared assets
needed to regenerate the container, metadata, listing, and application rather
than relying on existing generated files.

The established `CALL_HL`, `CALL_IX`, and `CALL_IY` macros were also
documented in `docs/ez80_hacks.md`. They synthesize the eZ80's missing
indirect-call forms by pushing the 24-bit `$+6` continuation before jumping
through the selected register. The documentation distinguishes this from a
real-call plus tail-jump callback trampoline, which preserves `BC`.

## Major milestone: containerized audio loads and plays end to end

Added an independent audio harness under `examples/agnb/audio`. Its local
preparation step converts 22 Wolf3D source effects into standard mono,
unsigned 8-bit PCM WAV files while preserving their 16,384 Hz sample rate and
frame counts. The container writer extracts only the PCM payloads and emits a
provisional AGNB 0.2 `sfx.agnb` containing 22 `LIST BUFR` records. Explicit
buffer IDs preserve Wolf3D's established `0xFB00` through `0xFB15` range.

The provisional three-byte `AUDI` descriptor stores VDP format `0x09`
(unsigned 8-bit mono with an explicit sample rate) followed by the little-
endian u16 sample rate. Independent byte-level validation confirmed all RIFF,
LIST, chunk, padding, metadata, buffer-ID, and PCM payload bytes in the
291,664-byte container.

Scaffolded the assembly harness from the hardware-proven image loader while
preserving its generic MOS, RIFF, bounds, block-streaming, buffer-clear,
buffer-load, and consolidation routines. The audio path validates
`BHDR`/`AUDI`/`DATA` before reading PCM, streams and consolidates each explicit
VDP buffer, creates an unsigned sample with `vdu_buffer_to_sound`, plays the
complete sample, and waits for a keypress before advancing. The user confirmed
perfect sequential playback in the emulator.

Added a master audio build script that prepares WAVs, builds the container,
assembles the application, creates the local emulator instance, writes the
correct `mystuff/agon-utils/examples/agnb/audio/tgt` autoexec path, and deploys
`app.bin` plus `sfx.agnb`. The full build/deploy/launch workflow completed
successfully. This milestone establishes working image and audio container
implementations from which the canonical application-neutral AGNB API can now
be extracted.

## Wolf3D integration feedback retrofitted into the canonical API

The first production consumer exposed two integration requirements that the
standalone harnesses did not:

- Wolf3D needs an application hook after each completed image so it can reuse
  one loader for splash animation and console breadcrumbs.
- Wolf3D already owns the harness's fixed `0xB7E000` SRAM region for map and
  sprite state.

The canonical API therefore now supplies two compatible image entry points.
`agnb_load_images` selects an internal no-op callback, preserving the original
calling convention. `agnb_load_images_with_callback` additionally accepts an
image-complete callback in `HL`. The loader invokes it after bitmap
finalization while the record metadata is still valid. The implementation
uses a real `call` followed by a tail `jp (hl)`, so the callback's `ret`
resumes the loader without disturbing `BC`.

The API's 8 KiB transfer window is now allocated within the assembled image
instead of claiming a fixed application SRAM address. This costs 8 KiB in a
consumer binary but removes a hidden memory-map dependency; an explicitly
configurable external workspace can be added later if a size-constrained
application demonstrates the need.

AgonWolf3D merged this API with the new AGNB 0.2 audio path, generated a
22-record `sfx.agnb`, independently validated its records byte for byte,
completed a full build, and assembled successfully. Its existing image
callback behavior remains intact while the original loose sound-effect load
table and raw target files have been removed.

The user subsequently confirmed the complete Wolf3D application starts,
reaches gameplay, and plays the containerized sound effects successfully in
the emulator. This establishes the canonical AGNB 0.2 audio API in a
production application alongside three consecutive image containers and
their per-image callbacks.

Wolf3D subsequently applied the same application-neutral callback pattern to
audio loading. `agnb_load_audio_with_callback` accepts a completed-sample
callback in `HL`, while the original `agnb_load_audio` selects an internal
no-op callback. Wolf3D uses that boundary to redraw its splash, advance BJ,
and report sound progress after each of the 22 samples. The first audio
callback also replaces the final image loader's debug texture without adding
a separate cleanup special case.
