Accepted agondev as the target assembler and eZ80 `ADL=0` as the application

boundary, low-address layout, and mixed-mode hardware adapters remain open
implementation work.

## Display investigation

Confirmed that complete UART streaming cannot carry the 7,168-byte original
framebuffer at 60 Hz. A resident VDP bitmap with sparse deltas remains a
candidate.

Inspected EZ80 Framebuffer Agon and its upstream vga-ez80 driver as read-only
references. The driver provides direct RGB332 framebuffer scanout and a
320×240 60 Hz 15 kHz mode, avoiding UART pixel bandwidth. The original packed
1-bit framebuffer therefore needs presentation conversion or a more invasive
scanout design. The full mode consumes most CPU time and owns Timer 1, so CPU
margin and split-interrupt integration require measurement. No display backend
was accepted during this investigation.

## ARCH-001 started — direct GPIO VGA selected

The Author selected Tom's direct eZ80 GPIO VGA framebuffer as the firm display
direction at 2026-08-22 03:41 EDT. Stock VDP sparse updates and UART scanout
are out of scope for this port; a pseudo-scanout design may become a separate
future project. ARCH-001 now qualifies the direct driver and resolves its
framebuffer, orientation, MOS-integration, and interrupt boundaries.

Source inspection bounded the mode-8 CPU window and driver ownership. The
320×240 15 kHz mode consumes the complete 240-line visible period inside its
Timer 1 handler and leaves at most 22 of 262 scanlines, about 8.4% of raw CPU
cycles, for application work. It also owns Timer 1, GPIO C, GPIO D sync/audio
bits, UART receive handling, and the normal VDP vblank interrupt. The original
packed framebuffer must remain game-authoritative because collision and shield
logic read it directly; RGB332 is a presentation shadow.

Added a 305-byte agondev-built ADL=0 raster probe. It targets driver mode 8,
uses framebuffer `0x080000`, and draws a centered 256×224 orientation pattern.
The probe assembled and passed structural validation with SHA-256
`810067c500fc81e2858d256a7f37e0bcce1f8cbbab313ed834c47cf16b31b629`.
It has not been run: emulator use, firmware changes, and physical wiring remain
behind the Author gate.

The Author subsequently authorized Fab Agon Emulator use and visually checked
two launches of the Rainbow-MOS/resident-driver raster probe. Both showed the
expected centered orientation pattern correctly and stably. This validates
repeatable mode-8 entry and 24-bit framebuffer addressing in emulation. The
physical 15 kHz display and measured application-cycle margin remain open.

## Emulator-first original-core proof

The Author deferred HARDWARE-001 and activated PORT-001 at 05:32 EDT to obtain
an emulator proof of code correctness first.

Built ASMX 2.0b6 from `apws/230831-asmx` commit
`e59c4027eed490767009940d5c7096eb383486cf` as an independent reference tool.
The preserved source emits an 8,192-byte ROM with SHA-256
`7446e0994117596de5206519e693f8875ff3455e0be121d5cb975c3bcc224c4e`.

Added an agondev ADL=0 proof loader above logical `8000`. It copies the exact
ROM to its original `0000-1fff` addresses, retains original RAM at
`2000-3fff`, and runs a deterministic harness at `4000`. Five tests exercise
the original `InitAliens`, `AddDelta`, `GetAlienStatPtr`, and `CountAliens`
machine code without reaching hardware I/O.

The first emulator iterations exposed two harness-boundary defects after the
tests themselves reached PASS: attempting to return after replacing SPS, and
using `RET.LIS` after a short `CALL`. The terminal proof now disables
interrupts after replacing the low vectors, uses short `CALL`/`RET`
consistently, and remains in a diagnostic loop instead of returning to MOS.

The Author visually confirmed the corrected stock-firmware emulator run is
stable at `Space Invaders original-core proof: PASS`; only the normal stock
VDP cursor flashes. This accepts the first emulator correctness gate.

The same stack evidence corrected the earlier setup probe. MOS `_exec16`
enters ADL=0 code with `CALL.IS`, so a returning probe must preserve that
frame and use `RET.LIS`; setting SPS to `fffe` destroyed it. The setup probe
now leaves SP untouched. The terminal game/proof path may still establish its
own original stack because it does not return to MOS.

## Address-preserving I/O adapter proof

Inventoried 42 executable hardware instructions in the reference ROM,
including shift-register operations encoded inside raw `DB` blocks. Added an
agondev adapter proof that replaces each two-byte instruction with `RST 0`
plus a typed port descriptor. The high-memory trap advances the return address
over the descriptor and preserves original registers and flags, so no later
ROM address moves.

Implemented inert input and sound/watchdog latches plus the original retained
16-bit shift-register formula. The proof also suppresses all five original
`EI` sites, runs original initialization and packed status rendering, and
stops diagnostically at the first splash-loop delay. Static validation passes
for the complete opcode inventory and byte-identical embedded ROM. Human
emulator validation initially produced a stable FAIL because byte-aligned
status text did not exercise the original hardware shifter; that was an
invalid proof assumption, not an initialization failure.

Revised the proof to check packed status VRAM separately and invoke original
`DrawSprite` explicitly with sprite byte `81` at bit offset 3. The adapter
performed two port-4 writes and two port-3 reads and produced expected adjacent
framebuffer bytes `08 04`. Failure messages now identify status VRAM, shift
trap count, shift value, or sound latch independently.

The Author visually confirmed the revised proof remained stable at
`Space Invaders adapter/init proof: PASS`. No sprites were visible because the
proof intentionally leaves original packed VRAM private; only the MOS result
and normal flashing VDP cursor are presented. PORT-001-W03 and W05 are
accepted.

## First opcode-exact agondev translation slice

Started PORT-001-W04 with seven address-bounded routines representing calls,
conditional flow, stack use, direct/indirect memory, pointer arithmetic,
rotates, and loops. Agondev emitted 121 bytes identical to the independent
ASMX reference at original addresses `00b1`, `01c0`, `01d9`, `1554`, `1581`,
`1a32`, and `1a47`.

The initial comparison rejected `GetAlienStatPtr` because the translation
omitted its third `ADD B`. Restoring that instruction produced a complete
byte match, demonstrating that the per-range oracle catches plausible manual
transcription errors before translated code is admitted to the port.
